# Периодическое фоновое получение Android — 0.2.7

Режим выбран пользователем для телефона с Android 15: без дополнительного
push-приложения. Установите APK поверх прежнего клиента без очистки данных.
Откройте профиль и включите «Фоновое получение» внизу списка бесед.
Это отдельное согласие на доступ к существующему профилю без открытого
интерфейса. Уведомления включаются своим переключателем.

По умолчанию фон выключен. Android WorkManager хранит одно уникальное
периодическое задание с ограничением «есть сеть». Первая попытка планируется
примерно через минуту после включения; далее интервал — 15 минут. Это не
гарантированное время: Doze, энергосбережение и ограничения производителя
могут задерживать запуск. Фоновая служба с постоянным уведомлением и push
не используются. Принудительная остановка приложения в настройках Android
останавливает задания до следующего ручного запуска. Обычное сворачивание,
блокировка экрана и системное завершение процесса не равны force-stop.

Расписание сохраняется после перезапуска и восстанавливается WorkManager
после перезагрузки телефона. Работать с профилем можно только после первого
разблокирования устройства. При открытом интерфейсе фоновый проход пропускается:
действует прежняя автосинхронизация на экране. Скрытие приложения не создаёт
частый JavaScript-таймер. Ошибки сети повторяются с увеличивающейся задержкой.
Выключение отменяет задание и запрещает новые запросы фонового прохода;
уже начатая операция может завершить сохранение и подтверждение.

## Профиль и приватность

Activity и Worker используют один process runtime и единственный Rust actor.
JNI инициализирует Android Keystore из доверенного application Context, без
запуска Activity/WebView. Путь фиксирован: `Context.dataDir/profile.sqlite`,
совпадает с прежним Tauri app_data_dir. Фон проверяет наличие базы и защищённого
ключа и не создаёт новый профиль. Файловая блокировка и прежний ключ сохраняются.
Открытый внутренний worker не открывает профиль в UI: отдельный presentation
gate выдаёт закрытый статус без ника до явного «Открыть профиль».

Каждый проход последовательно проверяет максимум 100 подходящих контактов,
с бюджетом времени и числовым курсором для продолжения. Доступ к actor общий:
открытый чат и фон не становятся независимыми writers. Загрузка/сохранение
сообщения не снимает непрочитанное и не отправляет квитанцию прочтения.
Существующие inbox/outbox, ACK и защита от повторов используются без новой
схемы базы. После фонового изменения UI обновляет историю и счётчики через
пустой локальный сигнал, даже если следующий сетевой запрос получил 0 сообщений.

Системное уведомление остаётся общим: «Новое сообщение в КотоПизделке».
У WorkManager нет текста, ника, ключей, маршрута или contact ID в input/output
Data. В настройках фонового режима сохраняются только согласие и числовой
курсор. Модуль уведомлений получает application Context и boolean просмотра,
не хранит Activity. Его ограниченная очередь не блокирует actor.
База профиля остаётся v5; сервер example deployment и общий Caddy не меняются.
Windows 0.2.7 получает общие изменения отображения прогресса; фоновый worker
и его настройки предназначены для Android.

## Проверка на телефоне

1. Обновите приложения. На телефоне откройте профиль, включите уведомления
   и фоновое получение.
2. Сверните клиент кнопкой «Домой» и заблокируйте экран. Отправьте сообщение
   с ПК и оставьте его клиент открытым до отправки в relay.
3. Дождитесь проверки Android: первая попытка примерно через минуту,
   но ОС может перенести её. Для повторной проверки оставьте телефон
   заблокированным на 15–30 минут или дольше при энергосбережении.
4. Нажмите уведомление, откройте профиль и проверьте сообщение/счётчик.
   Повторная синхронизация не должна создать дубликат.
5. Перезапустите приложение и проверьте сохранение переключателя. Выключите
   фон: сообщения должны по-прежнему получаться после открытия клиента.
6. Отдельно проверьте перезагрузку телефона с первым разблокированием.

В облаке проверяются actor, граница открытия UI, React, Kotlin/NDK и пакеты.
Настоящий запуск JobScheduler/Doze и показ уведомления при заблокированном
экране требуют проверки пользователем на Android 15.
