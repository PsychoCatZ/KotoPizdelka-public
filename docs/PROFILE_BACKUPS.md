# Резервная копия профиля — 0.2.11

Сохраняется отдельный файл `.kotobackup` с паролем. Он переносим между Windows
и Android: для восстановления не нужны прежние DPAPI/Keystore, пользователь
Windows или старое устройство. Пароль копии не сохраняется и не отправляется
на relay. Без пароля восстановить файл нельзя.

## Как пользоваться

Обновить клиенты поверх 0.2.10, сохранив данные. Relay и VPS обновлять не нужно.
Открыть профиль → «Настройки» → «Резервная копия профиля» → «Сохранить копию».
Придумать длинную парольную фразу (12–128 символов), повторить её и выбрать
новое имя файла. Файл с существующим именем на Windows не перезаписывается.
На Android используется системный выбор документа; дополнительных разрешений
на всё хранилище и Google-сервисов нет. Если выбрать облачное хранилище,
туда попадёт именно зашифрованный архив.

Затем выбрать «Проверить копию», указать файл и тот же пароль. Проверка
расшифровывает копию и проверяет SQLite, зашифрованные записи и возможность
подготовки восстановления в отдельном временном хранилище. Текущий профиль
не заменяется, старые чаты продолжают работать. Проверка не переносит профиль.
Хранить файл отдельно от устройства; пароль — отдельно от файла.

## После потери устройства

Установить 0.2.11 или более новую совместимую версию на устройство без профиля.
До первого нажатия «Открыть профиль» выбрать «Восстановить копию», подтвердить,
что прежнее устройство больше не использует этот профиль, и выбрать файл.
Существующий профиль не перезаписывается и не объединяется с архивом. Эта
функция не подключает дополнительное устройство к работающему профилю.

Возвращаются история на момент снимка, контакты, имена, непрочитанные и ключ
идентичности аккаунта. В аккаунт войти заново с прежним логином/паролем.
Восстановление само по себе не отзывает сессии на потерянном устройстве;
управление устройствами и отзыв их доступа — отдельный следующий этап.

**Старые беседы становятся архивом для чтения.** Для новых сообщений добавить
собеседника заново по логину или приглашению. Отправлять из старой копии
криптографической сессии нельзя: это возвращало бы старое состояние цепочек
ключей и создавало риск повторного использования ключей. Поэтому старые
маршруты удаляются, отправка/синхронизация блокируются и после перезапуска,
а старые незавершённые запросы знакомства помечаются удалёнными. История
остаётся в отдельном прежнем разговоре, пока пользователь сам не удалит его.

Сообщений после момента снимка в копии нет. Архив не продлевает срок действия
серверных очередей/приглашений и не возвращает удалённую на сервере доставку.
Для двух активных устройств одного аккаунта нужна отдельная архитектура
устройств и сессий; копирование этой базы её не заменяет.

## Формат и границы

Фиксированный versioned header `KotoPizdelka.profile-backup.v1`, случайные salt
16 байт и nonce 24 байта; Argon2id v19 с 64 MiB, t=3, p=1 и 32-байтным ключом;
XChaCha20-Poly1305 с аутентификацией всего header. Параметры KDF не берутся из
непроверенного файла, поэтому архив не может запросить произвольный объём KDF.
Внутри — ключ хранилища и согласованный SQLite-снимок через backup API.
Максимум файла — 128 MiB. Пароль и временные расшифрованные буферы обнуляются
на уровне нативных Zeroizing-обёрток; абсолютного отсутствия копий в памяти ОС,
WebView/IME или на скомпрометированном устройстве это не обещает.

Экспорт сериализуется тем же Rust actor, что и получение/отправка. Ключ
хранилища не выходит в WebView. Пути задаёт только нативный выбор файла;
попытки создать внутренние requests с путём через JSON IPC отвергаются.
Android переносит через приватный cache только непрозрачные архивы, а не
ключи или расшифрованный текст. Незавершённый внешний файл после ошибки
хранилища следует удалить вручную и экспортировать заново; «Проверить копию»
обнаруживает повреждение.

Восстановление сначала проверяет копию в отдельном приватном каталоге,
повторно защищает ключ средствами нового устройства и публикует пару
база/защищённый ключ без перезаписи. Прерванная публикация завершается при
следующем открытии профиля только при совпадении хешей подготовленных файлов;
непохожие существующие данные не заменяются. Поведение при аппаратном сбое
питания отдельно не проверено.

Локальная схема становится **v8** только после проверки прежнего ключа.
Обычное обновление не архивирует существующие чаты. Старый клиент 0.2.10 не
открывает v8: не откатывать приложение после обновления. Серверные резервные
копии и Windows DPAPI-архивы relay не меняются.
